# n8n workflows

Two workflows, both self-contained JSON you import into n8n:

- `ask-the-room.json`: the **project workflow**. A live log of every spoken question (what the rig heard,
  how it understood it, what it said, how long it took), plus a health check every 5 minutes. See below.
- `ask-the-repo.json`: a chat bot that answers questions about the **codebase**, for the team. See *Ask the Repo*.

## Ask the Room (project workflow)

Visitors ask out loud; nobody types. The rig listens all the time: Silero VAD, whisper.cpp, an overheard
gate that drops speech not meant for it, then the rule parser with Qwen3 1.7B (llama.cpp) for what the rules
can't read, answers (templates, or the local Qwen for open questions), voice and laser (`main.py`). The mic is
muted while the rig speaks, and the clicker is a "listen now" override. Everything real-time runs on the
Jetson, offline. n8n runs on the laptop, around the rig, and never slows an answer down.

The workflow JSON is generated by `scripts/gen_n8n_workflow.py`. Edit the script, then run
`python3 scripts/gen_n8n_workflow.py` from the repo root and re-import.

```
rig: mic ─▶ VAD ─▶ whisper ─▶ gate ─▶ rules │ Qwen ─▶ answer ─▶ speak + laser ─▶ POST webhook (background)
                                                                                   │
n8n: Rig heard a question ─▶ Settings ─▶ Token OK? ─▶ Read the question ─▶ went wrong? ─▶ alert
                                              └─ no ─▶ Reject: bad token (fails, nothing processed)
     every 5 min ──────────▶ Settings ─▶ GET /state ─▶ GET Qwen /health ─▶ Check the room ─▶ problems? ─▶ alert
                                             └─ rig unreachable ─▶ alert
alert: Discord set? ─▶ yes ─▶ POST to the Discord webhook
                    └─ no ──▶ Stop and Error (the execution shows red)
```

- **Rig heard a question.** For every question it answers, `main.py` posts
  `{heard, intent, object, understood_by (qwen | rules | gate), qwen_ms, answer, point_at, action,
  laser_err_cm, online, mode (asked | overheard), ignored_since_last, stt_ms, ask_s, record_transcribe_s, t}`
  plus `click_to_laser_s` (asked, with the clicker) or `speech_end_to_laser_s` (overheard), in a background
  thread. `ignored_since_last` only counts the overheard speech the rig dropped since its last answer; that
  text is never stored or sent. Each question is one execution, so *Executions* reads like a transcript of
  the demo. It raises an alert when nothing was heard, an open question got the fallback sentence ("I can
  tell you where things are, ...": the local Qwen couldn't answer, so check llama-server), the answer took
  over 3 s to reach the laser, Qwen took over 1 s, or the laser landed over 3 cm off.
- **Shared token.** Set `webhook_token` in *Settings* to the same value as `n8n.token` in the rig's
  `config.yaml`. The rig sends it as the `x-askroom-token` header; posts without it are rejected (the
  execution fails with "bad token" and nothing is processed). Empty means no check.
- **Health check** flags Qwen not answering (questions fall back to the rule parser and open questions get
  the fallback sentence), perception under 10 fps, and no internet (voice falls back from ElevenLabs to Piper
  and SMS can't go out; questions are still answered on the rig). Objects lost (UNKNOWN) are flagged after
  `unknown_grace_min` (2) minutes and objects carried off the table (GONE) after `gone_grace_min` (10)
  minutes, measured from the entity's `last_seen` against `/state`'s `server_t` (both the rig's wall clock).
  A pocketed pill bottle is part of the demo, so it isn't flagged straight away. Hidden objects (INSIDE,
  UNDER, HELD) are normal and never flagged.
- **Alerts** go to Discord when `discord_webhook_url` is set (Discord channel → Edit Channel →
  Integrations → Webhooks → Copy URL; no n8n credential needed). Without it they fail the execution, so it
  shows red under *Executions*.
- **SMS** stays on the rig's own `/sms` route (Twilio signature check and whitelist). n8n isn't involved.
- **Grok** isn't on the voice path. The sticky note describes its planned, detection-side role only.
- **Basic Auth on a chat trigger** (from the planning notes) doesn't apply here: this workflow has no chat
  trigger any more. The webhook is protected by the shared token instead. (Ask the Repo's chat trigger is a
  separate workflow; see its notes below.)

### Setup (self-hosted on the laptop, about 2 minutes)

1. Start n8n: `npx n8n`, or `docker run -it --rm -p 5678:5678 -v n8n_data:/home/node/.n8n n8nio/n8n`.
   Open http://localhost:5678.
2. **Create workflow → ⋯ → Import from File** → `n8n/ask-the-room.json`. No credentials are needed.
   **Save**, then **Publish** (the webhook only listens once published).
3. Open the **Settings** node:
   - `rig_url` and `qwen_url`. The Jetson over USB-C: `http://192.168.55.1:8000` and
     `http://192.168.55.1:8081` (the defaults). `python main.py --fake` on the same laptop:
     `http://127.0.0.1:8000` and `:8081`. Use `127.0.0.1`, not `localhost`: n8n resolves `localhost` to
     IPv6 `::1`, and the rig only listens on IPv4. n8n in Docker, rig on the same laptop:
     `http://host.docker.internal:8000`.
   - Optional: `discord_webhook_url`, `webhook_token`, `gone_grace_min`, `unknown_grace_min`.
4. On the Jetson, start Qwen so the laptop can reach it: `QWEN_HOST=0.0.0.0 scripts/qwen_server.sh`.
5. In the rig's `config.yaml`, point the rig at the webhook (the laptop is `192.168.55.100` over USB-C):
   `n8n: webhook_url: http://192.168.55.100:5678/webhook/ask-the-room` and, if you set one, `token:`.
   An empty `webhook_url` turns reporting off.

Tested with n8n 2.40.7: asked and overheard answers (pass), the fallback sentence and nothing heard (alert),
a wrong or missing token (rejected), alerts to a local stand-in for Discord and, without Discord, Stop and
Error; the scheduled check against `main.py --fake --no-voice` and a stub `/state` (GONE and UNKNOWN
flagged only after their grace time), with llama-server up and down, the rig offline, and the rig
unreachable (refused and timed out).

# Ask the Repo (n8n)

`ask-the-repo.json` is an n8n chat bot that answers questions about this codebase, for example "how does
the world model decide an object is UNDER something?", "where's the laser calibration?" or "what's left to
build?". It uses Claude Sonnet 5 and reads the repo live from GitHub, so it always sees the latest `main`.

```
chat message ─▶ Load CONTEXT.md (GitHub, main) ─▶ Project Guide (AI agent, Claude Sonnet 5, 10-message memory)
                                                     ├─ read_repo_file   open any file
                                                     ├─ list_repo_dir    list a folder
                                                     └─ recent_commits   last 15 commits on main
```

Each message starts from `CONTEXT.md` at the repo root, which is the project map. The agent then opens
the files it needs before answering. **Keep `CONTEXT.md` current**: the bot is only as up to date as that
file and the code. You don't need to re-import the workflow after editing it.

## Setup (one person, about 5 minutes)

1. Import the workflow. In n8n, choose **Create workflow → ⋯ → Import from File** and pick `n8n/ask-the-repo.json`.
   Tested against n8n 2.40.7. Any recent 2.x should work.
2. Create two credentials:
   - **Anthropic**: an API key from console.anthropic.com. Select it on the *Claude Sonnet 5* node.
   - **GitHub API**: a [fine-grained token](https://github.com/settings/personal-access-tokens/new)
     scoped to `anshulk08/asktheroom` with **Contents: read** (Metadata: read is added automatically).
     The repo is private, so this is required. Select it on *Load CONTEXT.md*, *read_repo_file*,
     *list_repo_dir* and *recent_commits*.
3. **Save**, then **Publish** (older versions call this *Activate*).
4. Open *When chat message received* and copy the **public chat URL**. Share that link with the team.
   Nobody else needs an n8n account.

The chat URL has to be reachable by everyone, so n8n Cloud is the easiest host. If you self-host
(`docker run -it --rm -p 5678:5678 -v n8n_data:/home/node/.n8n n8nio/n8n`), it's only reachable on your own
machine unless you put it behind a tunnel.

## Notes

- Anyone with the chat URL can use the bot and spend your Anthropic credits, and it can read the private
  repo through your token. Share the link only within the team. If that's a concern, switch the chat
  trigger's authentication to Basic Auth.
- The bot can't open the spec (a Claude Doc). It points people to the link instead.
- To change the model, pick a different one on the *Claude Sonnet 5* node. The answering rules are in the
  *Project Guide* node's system message.
